# 03_StateGraph

01_LangChain と同じ例を、StateGraphで書き直したサンプルです。

処理の流れを、「状態」「ノード」「辺（エッジ）」の組み合わせとして宣言します。

プロンプトとチェーンは 01_LangChain と同じです。

異なる点は「処理の流れの書き方」だけです。

01_LangChain と 03_StateGraph の 同じ番号のファイルを比較すると違いが見えます。

## Graph API の考え方

| 部品 | 役割 |
|---|---|
| 状態（State） | グラフ全体で受け渡すデータ。`TypedDict` で項目を決める。`MessagesState` は会話の履歴（messages）を持つ状態 |
| ノード | 処理の1ステップ。状態を受け取り、更新する項目だけを辞書で返す |
| 辺（`add_edge`） | 次に実行するノード。1つのノードから複数のノードへ辺を引くと、同時に実行される |
| 条件付きの辺（`add_conditional_edges`） | 状態を見て、次に進むノードを選ぶ。分岐や繰り返しに使う |
| `compile()` | グラフを実行できる形にする。`checkpointer`・`store` もここで渡す |
